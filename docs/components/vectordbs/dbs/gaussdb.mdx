---
title: "GaussDB"
description: "Use GaussDB centralized A-mode Ustore as a Mem0 vector store with native floatvector, BM25, and metadata filtering."
---

GaussDB support stores Mem0 memories in a centralized GaussDB Ustore table and uses native database capabilities for retrieval:

- `FLOATVECTOR` for semantic vector search
- `gsdiskann` or `gsivfflat` for vector indexes
- native BM25 on `text_lemmatized` for `keyword_search`
- metadata filters for `user_id`, `agent_id`, and `run_id`

The provider targets GaussDB `506` centralized deployments running in A compatibility mode with Ustore tables. It has also been live-validated against GaussDB Kernel `507.0.0 build 1268bd4d`.

### Driver

Use the GaussDB official `psycopg2` driver package for your GaussDB build. Do not use PyPI `psycopg2-binary` as the production default driver unless your GaussDB team has validated it for your database version.

The provider imports the driver through the `psycopg2` API and uses `ThreadedConnectionPool`.

### Usage

Most applications only need to provide GaussDB connection information. Vector index, BM25, Ustore, scoped filters, retries, and capability probes use production defaults.

```python Python
import os
from mem0 import Memory

os.environ["OPENAI_API_KEY"] = "sk-xx"
os.environ["GAUSSDB_DSN"] = "postgresql://gaussdb_user:gaussdb_password@127.0.0.1:19995/postgres"

config = {
    "vector_store": {
        "provider": "gaussdb",
        "config": {},
    },
}

memory = Memory.from_config(config)
memory.add("I prefer window seats on morning flights.", user_id="alice")
results = memory.search("flight seat preference", filters={"user_id": "alice"})
```

You can also put the DSN directly in the config:

```python Python
config = {
    "vector_store": {
        "provider": "gaussdb",
        "config": {
            "connection_string": "postgresql://gaussdb_user:gaussdb_password@127.0.0.1:19995/postgres",
        },
    },
}
```

### Config

Most users should start with the minimal connection fields below.

| Parameter | Description | Default Value |
| --- | --- | --- |
| `connection_string` / `dsn` / `url` | GaussDB DSN; overrides individual connection fields | `GAUSSDB_CONNECTION_STRING`, `GAUSSDB_DSN`, or `GAUSSDB_URL` |
| `host` | Database host | `GAUSSDB_HOST` |
| `port` | Database port | `GAUSSDB_PORT` |
| `database` / `dbname` | GaussDB database name | `GAUSSDB_DATABASE`, `GAUSSDB_DBNAME`, or `postgres` |
| `user` | Database user | `GAUSSDB_USER` |
| `password` | Database password | `GAUSSDB_PASSWORD` |
| `collection_name` | Collection table name | `mem0` |
| `embedding_model_dims` | Embedding vector dimension | `1536` |

Advanced parameters are optional and should usually be changed only for tuning, compatibility fallback, or operations.

| Parameter | Description | Default Value |
| --- | --- | --- |
| `connection_pool` | Existing `psycopg2` pool | `None` |
| `minconn` / `maxconn` | Connection pool bounds | `1` / `5` |
| `sslmode` | SSL mode | `None` |
| `sslrootcert` | SSL root certificate path | `None` |
| `client_encoding` | Client encoding used by `psycopg2` connections | `UTF8` |
| `table_storage` | Table storage type | `ustore` |
| `compatibility_mode` | Compatibility mode | `A` |
| `gaussdb_version_baseline` | Commercial baseline family | `506` |
| `id_column_type` | `uuid` or `varchar` | `uuid` |
| `vector_index_type` | `gsdiskann` or `gsivfflat` | `gsdiskann` |
| `vector_index_maintenance_work_mem` | Session-local `maintenance_work_mem` used while building vector indexes | `128MB` |
| `vector_metric` | `cosine` or `l2` | `cosine` |
| `bm25_enabled` | Enable native BM25 keyword search | `True` |
| `bm25_fail_fast` | Raise BM25 errors instead of semantic-only fallback | `False` |
| `bm25_ranking_metric` | GaussDB BM25 ranking metric; `0` is BM25_OKAPI | `0` |
| `bm25_ncandidates` | GaussDB BM25 candidate count | `128` |
| `bm25_dictionary` | Optional BM25 dictionary | `None` |
| `metadata_column_mode` | `jsonb`, `text`, or `redundant_columns` | `jsonb` |
| `allowed_filter_keys` | Optional metadata filter allowlist | `None` |
| `require_scoped_filters` | Require scoped read filters | `True` |
| `scope_filter_keys` | Scoped filter keys | `["user_id", "agent_id", "run_id"]` |
| `enable_capability_probe` | Probe vector, BM25, and metadata capabilities on init | `True` |
| `slow_query_ms` | Slow query warning threshold | `1000` |
| `retry_attempts` | Retry attempts for transient database failures | `2` |

### Defaults

The default vector metric is `cosine`. Semantic search uses the `FLOATVECTOR` cosine distance operator `<+>` and creates vector indexes with `COSINE`, for example:

```sql
CREATE INDEX memories_vector_idx
ON memories
USING gsdiskann (vector COSINE);
```

BM25 uses GaussDB native defaults unless overridden:

- `bm25_ranking_metric = 0`
- `bm25_ncandidates = 128`
- database/default dictionary

`require_scoped_filters` is enabled by default. In commercial deployments, `search`, `keyword_search`, `search_batch`, and `list` must include at least one of `user_id`, `agent_id`, or `run_id`. Disable this only for tests, migrations, or trusted administrator workflows.

### Capability Checks

Before production traffic, validate the target GaussDB environment:

```sql
SHOW enable_vectordb;

CREATE TABLE mem0_probe (
    id UUID PRIMARY KEY,
    vector FLOATVECTOR(1536),
    payload JSONB,
    text_lemmatized TEXT
) WITH (storage_type=ustore);

BEGIN;
SET LOCAL maintenance_work_mem = '128MB';

CREATE INDEX mem0_probe_vector_idx
ON mem0_probe
USING gsdiskann (vector COSINE);

COMMIT;

CREATE INDEX mem0_probe_bm25_idx
ON mem0_probe
USING bm25 (text_lemmatized)
WITH (storage_type='USTORE');

SELECT text_lemmatized ### 'probe' AS score
FROM mem0_probe
ORDER BY score DESC
LIMIT 1;
```

If `JSONB` or JSON expression indexes are unavailable in your A-mode environment, set `metadata_column_mode="redundant_columns"` to index `user_id`, `agent_id`, and `run_id` as normal columns.

### Operations

The provider includes helper methods for operational workflows:

- `migration_dry_run()` reports planned schema and backfill actions.
- `backfill_derived_fields(dry_run=True)` reports rows missing `memory` or `text_lemmatized`.
- `backfill_derived_fields(dry_run=False)` fills derived fields from payload values when possible.
- `analyze()` runs `ANALYZE` on the collection table.

Vector, BM25, and filter indexes are ensured internally when collections are created or reset. Plan explicit index
rebuilds as a database operations task because they can take locks and consume significant resources.

### Migration and Rollback

Use `migration_dry_run()` before changing collection schema or metadata mode. Review the planned actions and affected rows before running any mutating backfill.

Recommended rollout sequence:

1. Run capability checks against the target GaussDB `506` build.
2. Create a fresh collection with the target config.
3. Backfill or import records.
4. Run semantic, BM25, filter-isolation, and entity batch-search checks.
5. Switch Mem0 configuration to the GaussDB provider.

Rollback options:

- Before data migration: switch Mem0 back to the previous vector store provider.
- After data migration: restore from the database backup or keep the previous provider collection intact until replay checks pass.
- BM25-specific failure: set `bm25_enabled=False` only if semantic-only fallback is acceptable for the workflow.
- Vector capability failure: keep fail-fast behavior and do not serve traffic from the collection.

### Troubleshooting

| Symptom | Likely Cause | Action |
| --- | --- | --- |
| Import error for `psycopg2` | GaussDB official driver package is not installed | Install the GaussDB `psycopg2` wheel for your database build |
| Initialization fails on vector probe | `enable_vectordb`, `FLOATVECTOR`, or vector index support is unavailable | Check GaussDB version/build and vector feature enablement |
| `gsdiskann` index creation fails with `Maintenance_work_mem is below the required value` | The database memory setting is too low for DiskANN index build | Set `vector_index_maintenance_work_mem` to a larger value, increase the database/session `maintenance_work_mem`, or use `vector_index_type="gsivfflat"` for smaller test environments |
| BM25 is disabled | BM25 index creation or score query failed and `bm25_fail_fast=False` | Verify BM25 support on Ustore and check `storage_type='USTORE'` |
| Chinese or mixed-language payloads fail with JSON/encoding errors | The database `server_encoding` is `SQL_ASCII` | Use a UTF8 database in A compatibility mode for multilingual memories |
| Filter queries are slow | JSON expression indexes are unavailable or not used | Use `metadata_column_mode="redundant_columns"` |
| Read operation raises scoped filter error | `require_scoped_filters=True` and no tenant filter was supplied | Pass `filters={"user_id": ...}` or another configured scope key |
